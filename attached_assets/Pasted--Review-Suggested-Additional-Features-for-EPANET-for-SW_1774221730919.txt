## Suggested Additional Common Features to Add

### 1. **Pump Energy & Cost Analysis — Side-by-Side**

The app mentions that EPANET tracks pump energy costs while SWMM5 doesn't, but there's no interactive tool for it. A useful addition would be:

- An **interactive pump curve editor** where you draw/enter the H-Q curve and see how EPANET computes energy (kWh), efficiency, and cost per day
- Show the SWMM5 pump curve types (Type 1–4) mapped to EPANET's multi-point curve
- A **pump affinity law calculator** — EPANET's variable-speed pump modeling using speed ratios (N/N₀) to shift curves is a concept SWMM5 modelers rarely encounter
- Wire-to-water efficiency breakdown: motor efficiency × pump efficiency × variable frequency drive efficiency
- EPANET's`[ENERGY]` section explained through SWMM5 eyes — price patterns, demand charges, global/per-pump efficiency curves

### 2. **Valve Types — The Missing Deep Dive**

The app maps SWMM5 orifices/weirs → EPANET valves but doesn't explore EPANET's rich valve taxonomy in detail. SWMM5 modelers need to understand:

| EPANET Valve | What It Does | SWMM5 Nearest Analog |
|---|---|---|
| **PRV** (Pressure Reducing) | Limits downstream pressure to a set value | No direct equivalent — like a weir that caps HGL |
| **PSV** (Pressure Sustaining) | Maintains minimum upstream pressure | No equivalent |
| **PBV** (Pressure Breaker) | Forces a fixed pressure drop across the valve | No equivalent |
| **FCV** (Flow Control) | Limits flow to a set maximum | Closest to a SWMM5 orifice with a fixed opening |
| **TCV** (Throttle Control) | Variable minor loss coefficient (K) | Like a partially open SWMM5 orifice |
| **GPV** (General Purpose) | User-defined headloss vs. flow curve | Most flexible — like a custom SWMM5 rating curve |

An **interactive valve simulator** showing how each valve type modifies the HGL would be very valuable. SWMM5 modelers think in terms of weir/orifice equations (Q = CdA√2gH); they need to see how PRVs and PSVs operate on the pressure domain instead.

### 3. **Demand Allocation Methods**

EPANET modelers spend significant time on demand allocation — distributing total system demand to individual nodes. This is a workflow concept completely absent from SWMM5 (where subcatchments generate their own inflows). Cover:

- **Unit demand methods**: demand per linear foot of main, per service connection, per land use area
- **GIS-based allocation**: assigning meter/billing data to nearest junction
- **Demand categories**: residential, commercial, industrial, fire flow — each with its own diurnal pattern
- **Pressure-dependent demand (PDA)** vs. **demand-driven analysis (DDA)** — the app mentions this but an interactive simulator showing how PDA reduces demand at low pressure would be powerful
- **Unaccounted-for water / non-revenue water**: how to represent background leakage using emitters (Q = C·P^γ) distributed across the network

### 4. **Network Topology — Looped vs. Branched**

This is a fundamental structural difference that deserves its own section:

- **SWMM5 networks** are typically **dendritic** (tree-shaped) — flow goes from many upstream subcatchments toward one or a few outfalls
- **EPANET networks** are typically **heavily looped** — water has multiple paths from source to customer for redundancy

An interactive visualization showing:
- How EPANET solves looped networks (simultaneous equations for all loops)
- Why SWMM5's kinematic wave can't handle loops (flow can only go downstream)
- Why SWMM5's dynamic wave CAN handle loops (backwater propagation)
- The concept of **pressure zones** in EPANET — elevation-based service areas separated by PRVs or pumps, which has no SWMM5 equivalent

### 5. **Calibration Comparison**

The app mentions calibration briefly but this deserves a dedicated interactive section:

| Aspect | SWMM5 Calibration | EPANET Calibration |
|---|---|---|
| **Primary data** | Flow & depth hydrographs at monitoring manholes | Pressure at hydrant tests, tank level recorders, SCADA flows |
| **Key parameters** | Subcatchment: imperviousness, width, slope, infiltration params. Conduit: Manning's n | Pipe: roughness C. Junction: demand. Emitter coefficients for leakage |
| **Time scale** | Event-based (individual storms, hours) | Operational (diurnal cycles, days to weeks) |
| **Difficulty** | High — nonlinear hydrology + hydraulics | Moderate — primarily roughness adjustment |
| **Tools** | SRTC (SWMM5 Calibration), manual, PEST | Darwin Calibrator, WaterGEMS, manual C-factor adjustment |
| **Fire flow test** | N/A | The gold standard for EPANET calibration — measured pressure drop at known flow |

### 6. **Fire Flow Analysis**

This is one of EPANET's most common practical applications and has zero SWMM5 equivalent:

- How to set up fire flow analysis: add a demand at a node, check if residual pressure stays above 20 psi
- Available fire flow calculation: what's the maximum flow at 20 psi residual?
- Fire flow duration considerations (typically 2–4 hours)
- An **interactive fire flow calculator** where you pick a node, set the required residual pressure, and the tool calculates available fire flow based on the system curves
- ISO rating implications (Insurance Services Office fire suppression rating)

### 7. **Skeletonization — Model Simplification**

Both SWMM5 and EPANET models often need simplification, but for different reasons and using different techniques:

- **EPANET skeletonization**: removing small-diameter pipes (< 6"), collapsing series pipes, merging close junctions, redistributing demands to remaining nodes. The goal is faster computation without losing pressure accuracy at key nodes.
- **SWMM5 simplification**: combining subcatchments, lengthening short conduits (to satisfy Courant), lumping parallel pipes, simplifying storage geometry. The goal is numerical stability and reasonable runtimes.
- An interactive tool showing how merging two EPANET pipes in series works (equivalent L, D, C) vs. how combining two SWMM5 conduits works (different because of storage/inertia effects)

### 8. **Design Criteria Comparison**

| Design Parameter | SWMM5 (Collection) | EPANET (Distribution) |
|---|---|---|
| **Pipe sizing target** | d/D ≤ 0.8 at design flow | Velocity 2–5 ft/s; pressure 40–80 psi |
| **Minimum velocity** | 2.0 ft/s (self-cleansing) | 0.5 ft/s (avoid stagnation / water age) |
| **Maximum velocity** | 10–15 ft/s | 5–8 ft/s (prevent erosion & water hammer) |
| **Minimum slope** | Per pipe diameter (Ten States Standards) | N/A (pressurized) |
| **Minimum cover** | 3–5 ft typically | 3–5 ft (freeze protection) |
| **Design storm** | 2-yr, 10-yr, 25-yr, 100-yr depending on jurisdiction | Maximum day demand + fire flow |
| **Failure mode** | Surcharge → flooding → CSO | Low pressure → no service → contamination risk |

### 9. **Pattern Editor — Diurnal Curves**

Both models use time patterns extensively:

- SWMM5: DWF patterns (hourly, weekend, monthly, seasonal)
- EPANET: Demand patterns (diurnal, weekend, seasonal)

An **interactive pattern editor** where you:
- Draw a diurnal curve for SWMM5 DWF and see the identical EPANET demand pattern generated automatically
- Compare typical diurnal curves: residential (morning/evening peaks), commercial (9-5), industrial (flat), combined sewer (DWF + I/I during wet weather)
- See peaking factors: max hour / average day, max day / average day
- Explore how EPANET patterns are cyclical (repeat) while SWMM5 time series can be arbitrary (non-repeating)

### 10. **SCADA Integration & Real-Time Modeling**

Both tools are increasingly used with real-time data:

- **EPANET-RTX**: Real-time extension for EPANET that ingests SCADA data (tank levels, pump status, pressures, flows) and runs the model in real-time or near-real-time
- **SWMM5 RTC**: Real-time control rules that simulate automated gate/pump control based on sensor readings
- **EPA-SWMM-R (SWMM5+)**: Emerging real-time capabilities
- How SCADA data maps to each model: tank level → EPANET tank initial condition; flow meter → SWMM5 inflow time series
- The concept of **state estimation** — using measured data to adjust model parameters in real-time

### 11. **Model Interoperability — Using Both Together**

Many real water/wastewater systems need BOTH models:

- The collection system (SWMM5) delivers flow to a treatment plant
- The treatment plant effluent enters the distribution system (EPANET)
- Combined sewer overflows (SWMM5) can contaminate source water for the distribution system (EPANET)

An interactive workflow diagram showing:
- How to pass SWMM5 outfall flows as EPANET reservoir inputs
- How to use SWMM5 to model the raw water collection → treatment → EPANET clearwell as a reservoir
- Commercial tools that integrate both (InfoWorks ICM, MIKE URBAN, PCSWMM/SWMM5+)

### 12. **GIS Integration Comparison**

| GIS Aspect | SWMM5 | EPANET |
|---|---|---|
| **Native GIS support** | None (coordinates only) | None (coordinates only) |
| **Common GIS tools** | PCSWMM, ICM, XPSWMM, QGIS plugin | WaterGEMS, WaterCAD, QGIS SKETCHER/epanet plugin |
| **Data sources** | LiDAR for elevations, land use for imperviousness, soil maps for infiltration, pipe survey for inverts | Pipe records (GIS/AM), billing data for demands, elevation (DEM), pressure zone boundaries |
| **Coordinate system** | [COORDINATES] section — same format | [COORDINATES] section — same format |
| **Background map** | SWMM5 GUI supports backdrop images | EPANET GUI supports backdrop images |

### 13. **Reporting & Output Comparison**

An interactive section showing how to read and compare output files:

- SWMM5`.rpt` file structure vs. EPANET`.rpt` file structure
- Key summary statistics: SWMM5's continuity errors (runoff, routing) vs. EPANET's system flow balance
- SWMM5 outputs: flow, depth, velocity, Froude number, capacity (d/D), flooding volume
- EPANET outputs: pressure, head, flow, velocity, headloss, water quality (concentration/age/trace %)
- How to interpret EPANET's energy report (kWh, cost, efficiency per pump)

### 14. **Age / Condition Assessment**

Both pipe networks deteriorate over time, but the modeling implications differ:

- **EPANET**: Aging → lower C-factor → higher headloss → lower pressures. Also affects wall reaction coefficient (kw) for chlorine decay. Old cast iron with tuberculation might go from C=130 to C=60.
- **SWMM5**: Aging → higher Manning's n → reduced capacity → earlier surcharging. Also root intrusion → I/I increases. Structural deterioration → CCTV condition grades.
- A **pipe aging calculator** that shows how C or n changes over time for different materials and water quality conditions

### 15. **Transient Modeling Bridge**

The app has a transient checklist but could add:

- A comparison of **EPANET → HAMMER/AFT Impulse** (for pressure transients) vs. **SWMM5 dynamic wave** (for free-surface transients)
- When SWMM5's Preissmann slot approximation of pressure waves is "good enough" vs. when you truly need a Method of Characteristics (MOC) transient solver
- Water column separation risk assessment — a calculator based on pipeline profile, steady-state velocity, and valve closure time

## Summary Prioritization

If I were to rank these by value to the target audience (SWMM5 experts learning EPANET):

| Priority | Feature | Rationale |
|---|---|---|
| 🔴 High | Valve types deep dive | Biggest conceptual gap — no SWMM5 equivalent |
| 🔴 High | Fire flow analysis | Most common EPANET use case with no SWMM5 parallel |
| 🔴 High | Pump energy/cost calculator | Unique EPANET capability, highly practical |
| 🟡 Medium | Demand allocation methods | Essential workflow knowledge for EPANET |
| 🟡 Medium | Network topology (looped vs. branched) | Fundamental structural difference |
| 🟡 Medium | Design criteria comparison | Quick-reference value |
| 🟡 Medium | Pattern editor | Practical tool with high reuse |
| 🟡 Medium | Calibration comparison | Bridges the workflow gap |
| 🟢 Lower | Skeletonization | Important but less conceptual |
| 🟢 Lower | SCADA/real-time | Advanced topic |
| 🟢 Lower | GIS integration | Tool-specific, less about concepts |
| 🟢 Lower | Reporting comparison | Reference material |

The app is already an **A+** technical resource. These additions would make it the definitive, encyclopedic reference for anyone crossing between the two hydraulic modeling worlds.
